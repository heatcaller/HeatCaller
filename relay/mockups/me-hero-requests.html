Ask the desk, hear back on the card

The "Up next" card ends in three small controls today: a See the running order text link and two plain buttons, Need 5 more minutes and Car broken - skip me. Each option below makes them big keys that belong to the card, and puts the desk's answer on the card the moment it comes back. Use the bar to step one request through: ready, asked, then the desk's yes or no. Tapping an ask key on a phone asks too.

Plan

A real push when the desk answers

Most of the road is already built. The answer already travels from the desk to the phone inside the driver's live document, and the relay already sends Web Push for "your race is next", marshal duty, "about 5 minutes" and results. The relay watches each new live document for changes, so a desk answer is one more change to watch for. Nothing new for the phone to sign up to.

In the relay (relay/)

src/push.ts
  1. Add askAlerts(before, after, url, atMs), called from the end of liveAlerts. For each ask in after.asks whose state is approved, noted or declined, push only if the same ref was waiting in before.asks. An ask that appears already answered also counts, provided its at is under 5 minutes old.
  2. Desk kinds only: late, skip, details, query. Pack, car, setup and packedit are applied by the laptop by itself, so they push only when declined.
  3. tag: "hc-ask-" + ref, so an undo then a re-answer replaces the alert instead of stacking. Keep the 600s TTL; a late "yes, 5 more minutes" is worse than none.
  4. Freshness guard (from the stale-calls rule): drop it if at is more than 5 minutes old by the document's own clock.
  5. url: the existing myNightUrl(club) with &s=tonight, so the tap lands on the card. Never a badge code.
src/mespaces.ts (after you pick)
  1. Draw the chosen option in meMoment(), from live.asks plus sentAsks, which the page already keeps. Show the newest desk-kind answer for 15 minutes after at, or until OK is tapped (seen refs kept per tab).
  2. Show the reply on every hero state, not just Up next. A skipped driver's card often moves on to another race, and Racing now still needs "yes, 5 more minutes" in view.
  3. When the page is open and a waiting ask turns answered: a short buzz and the existing beep, the same as other in-page alerts.
test/
  • A push.ts test: waiting→approved sends one; an unchanged answer, a pack auto-apply and a first-look document send none; a stale at sends none.
Ship
  • fly deploy from relay/, then restart HeatCaller, or phones keep the old page.

In the app (Driver Requests)

DriverAskContracts.cs · DriverRequests.cs · DriverLive.cs
  1. Give DriverAskAnswer an AnsweredUtc. AnswersFor already has r.AnsweredUtc to hand.
  2. DriverLive.AsksFor writes it as "at" (ISO, UTC) when there is one. This is what lets the relay and the card judge freshness.
MainForm.DriverRequests.cs · MainForm.DriverLive.cs
  1. Publish an answer at once. The store already bumps a version on every Changed(); the driverlive tick compares it with the version it last built for and sets _driverLiveDirty. Today an answer waits for the 10-second rebuild.
DriverRequestsForm.cs
  1. Decline already asks for a reason, and Race Control already writes the approval's words ("Held 5 minutes…"). Add one line under the buttons: "The driver's phone is told straight away." That way the desk knows the words they type go to a pocket.
  2. Optional, later: a short "Message to the driver" box on approve for details and queries, which today go back with no words.
  3. Undo (Reopen) needs nothing new. The phone goes back to "waiting", and the re-answer replaces the alert through its tag.
Limits to tell the user
  • The phone must have alerts switched on (the existing sign-up). Without it, the card still shows the answer next time the page is open.
  • On an iPhone, only from the club page added to the Home Screen (Apple's rule, already in push.ts).
  • The laptop must be online to the relay. An answer given offline is pushed when it reconnects only if it is still under 5 minutes old.
