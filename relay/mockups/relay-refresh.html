HeatCaller relay · UI update plan

Relay Refresh

One button kit and one set of colour tokens for every page the relay serves: the five club tabs, the pages under them, and the club's Manage desk. Below the plan, each tab has three directions to pick from. Switch the club look to check that every control follows it.

What's wrong today

  • Eight button styles that grew one page at a time: .go, .go.quiet, .page, .share, .btn, .rtab, .chip, the caption/ear toggles.
  • Colours written straight into rules, so they ignore the club look: Manage's danger #7a2233, the recorded chip's #0a2e17, the amber #F5B83D, the About sheet's #FF2E88, white text on live chips.
  • Manage uses --raised, --hair and --on-tint, which the club pages never define.
  • Share is a grey caps word, Newer/Older look like tags, and pressed states only exist on two toggles.

The kit

  • Primary: the one thing to do on a screen (Check in, Sign in, Listen live).
  • Tonal: a second action that still matters (Follow, Seed mains). Mixed from the primary, so it follows the look.
  • Outline: neutral actions (Newer, Older, Share, Details).
  • Ghost: inline links that act (What's HeatCaller?, Change).
  • Danger: tinted from --bad, never a literal.
  • Segmented: Results' sub-tabs, Me's race tabs, Manage's desk tabs.
  • Every control is at least 44px tall, shows a focus ring, shrinks a little when pressed and marks on/off with aria-pressed.

How it lands

  1. Add the missing tokens to the root block: --on-primary, --warn, --tonal, --ring, with --raised/--hair made aliases.
  2. Write the kit once in STYLE as .b + .b-pri/-ton/-out/-gho/-dan, .seg, .bar.
  3. Move each page's markup onto the kit, tab by tab, in the order you approve.
  4. Delete the old classes once nothing uses them; a test fails if a hex colour appears in a page rule.
  5. Check every tab on a phone in all four looks, then release notes.
